Workspace-модель для всех текущих сущностей

Цель: user больше не является главной границей production data. User получает доступ к workspace, а workspace владеет рабочими данными.

Куда переезжают сущности

Синие - shared справочники, бордовые - workspace-owned, медные - связующие таблицы.

Identity / Access
usersОстаются login identity.
accountsCompany/billing owner. Можно добавить позже.
workspace_membersuser_id + workspace_id + role.
Workspace boundary
workspacesГлавная граница данных: personal, jerky, cakes, test.
workspace_ingredientsРабочий набор: active/archived, local alias/category.
ingredientsShared dictionary: name, type, dedupe.
Production catalog
pricesworkspace_id + ingredient_id. История цен.
recipesworkspace_id вместо user_id.
recipe_ingredientsrecipe_id + ingredient_id. Через recipe попадает в workspace.
Sales catalog
packagesworkspace_id вместо user_id.
productsworkspace_id вместо user_id.
product_optionsproduct_id + recipe_id, both same workspace.
Operations / CRM
clientsworkspace_id вместо user_id.
ordersworkspace_id вместо user_id.
order_itemsorder_id + product_id, both same workspace.
Production runs
cooking_sessionsworkspace_id вместо user_id.
cooking_session_ingredientssession_id + ingredient_id. Ingredient must be in workspace set.
dashboardAll analytics query by workspace_id.

Правила миграции

Чтобы модель не расползалась, нужны жесткие инварианты.

1
User is identity, not data ownerНовые production queries должны брать `workspace_id`, а не только `user_id`.
2
Workspace owns operational dataRecipes, products, clients, orders, prices, packages, sessions живут в workspace.
3
Ingredient stays sharedСам ingredient остается справочником, но workspace решает, какие ingredients активны.
4
Cross-workspace references forbiddenProduct cannot reference recipe from another workspace; order cannot reference product from another workspace.
5
Personal workspace firstДля текущих users создаем default workspace и переносим все user-owned records туда.
Phase 1: foundationAdd workspaces, workspace_members, current workspace context, backfill one personal workspace per user.
Phase 2: migrate owner columnsAdd workspace_id to current user-owned tables, backfill from user_id, update controllers to enforce membership.
Phase 3: ingredient workbenchAdd workspace_ingredients, change ingredients screen to show workspace set, move prices to workspace scope.
Phase 4: account/companyAdd account ownership and team management UI when needed; personal workspaces can attach to accounts later.
