Account → Workspace → Production data

Workspace - рабочий контекст. Account/company можно добавить сверху, не ломая ингредиенты, цены и рецепты.

Как связаны сущности

Пользователь работает в выбранном workspace. Workspace может принадлежать account/company.

Account / Company Владелец бизнеса: компания, команда, личный аккаунт. Может появиться позже.
User Человек, который входит в систему. Сам user не должен быть главной data boundary.
owns many
joins through membership
Workspace Jerky production, Cakes, Test kitchen. Основная граница рабочих данных.
WorkspaceMember user_id + workspace_id + role. Здесь живут доступы и роли.
workspace owns operational data
WorkspaceIngredients Рабочий набор ингредиентов workspace: active/archived, optional alias/category.
IngredientPrices История цен внутри workspace: ingredient_id, price, quantity, unit, date.
Recipes / Products / Orders Постепенно переезжают с user_id на workspace_id.
Ingredients Общий справочник инсталляции для дедупликации: name, type.
workspace ingredients reference shared ingredients

Как это работает в UI

В интерфейсе пользователь всегда находится в текущем workspace.

1
Current workspaceВ шапке приложения появляется выбранный workspace. Все рабочие экраны фильтруются по нему.
2
Ingredients screenПоказывает workspace ingredients, а не весь installation-wide справочник.
3
Add to workspaceСначала ищем в общем ingredients; если нашли - добавляем связь. Если нет - создаем ingredient и связь.
4
PricesНовая цена пишется в историю текущего workspace. Другая команда не видит эту цену.
5
Migration pathСейчас каждому user создается personal workspace. Позже workspace можно привязать к account/company.
