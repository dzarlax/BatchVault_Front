Product And Package Modal Direction

Product create/edit is supported today. Package edit needs backend API work; package create is supported now.

A. Single Product Form
frontend only

Refine current modal

Keep one product modal, but make it denser: image URL becomes secondary/optional, package + recipes stay in details, package create remains a nested small modal.

B. Guided Product Flow
frontend only

Operational order

Fields follow the user's decision order: identity, package, recipes, then price/cost. Better for creation; slightly more scrolling for edits.

C. Package Manager
API required

Create and edit packages

Turns packaging into a real manager with edit actions. Requires backend routes such as PUT/PATCH /api/packages/:id and probably delete/usage rules.
